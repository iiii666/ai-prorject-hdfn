# 맡긴 업무

## 사용 흐름

1. **AI에게 조사하기**에서 질문하고 근거·수행 단계를 확인합니다.
2. “이 결과를 저장하고 매주 확인해줘”라고 요청합니다.
3. **업무 맡기기 · 초안 확인**에서 목적·조사 방식·일정·조사 시작 기준을 확인하고 **확인하고 업무 맡기기**를 누릅니다. 확인 전에는 저장하지 않습니다.
4. **맡긴 업무 열기**에서 **지금 확인하기**로 시험 실행하거나 **업무 시작**으로 정기 실행을 활성화합니다. 서버가 켜져 있을 때 동작합니다.
5. 최근 발견사항의 **근거 확인·후속 질문**에서 자동 조사와 같은 대화를 이어갑니다. **업무로 돌아가기**로 돌아올 수 있습니다.
6. 설정·활동 기록은 각 업무 안에서 펼쳐서 봅니다. 저장한 분석은 조사 화면의 보관함, 전체 이력 검색·과거 재현 시연은 **전체 활동 기록 찾아보기**에서 확인합니다.

## 조사 방식

- **규칙 점검:** 기존 임계값 평가와 정해진 추가 조회를 유지합니다. 기존 감시는 설정을 바꾸기 전까지 이 방식을 사용합니다.
- **실제 AI 조사:** 발견 그룹별로 모델이 집계 결과를 보고 다음 도구와 분석 축을 선택합니다. AI 키가 없으면 설정 필요로 표시합니다.
- **시연 · 규칙 기반 조사:** 실제 DB를 조회하되 모델을 호출하지 않습니다. 실제 AI 실행과 구분해 표시합니다.

새 업무는 원래 대화의 조사 모드를 기본으로 제안합니다. 자동 조사는 서버에서 브라우저 없이 진행되며 실행당 같은 지표의 변화량 절댓값이 큰 최대 3개 그룹을 순차 조사합니다. 각 조사에서 최대 6회 조회·8회 판단 및 기존 모델 호출 한도를 적용합니다. 나머지 그룹에는 조사 한도를 표시하고, 다음 실행에서 아직 조건에 해당하면 우선 조사합니다. 조건 발견과 AI 조사 성공은 별도 상태이며 실패·추가 확인·중단을 성공으로 표시하지 않습니다.

기간·점포·채널은 자동 조사 중 고정됩니다. 상품군·고객 등급 업무는 모든 조회에 해당 필터를 적용하고 후속 대화에서도 유지합니다. 이 범위를 지원하지 않는 앱 전환율·예산 도구는 거절합니다. 그룹 필터를 표현할 수 없는 분석 앱으로 저장하지 않으며 조사 대화로 근거를 보관합니다.

## 발견 추적

같은 설정·실행 유형의 직전 완료 실행과 비교합니다. 시험·정기·과거 재현은 섞지 않습니다. 기준이 바뀌면 새 추적을 시작합니다.

| 상태 | 판정 |
| --- | --- |
| 새로 발견 | 이전 미해결 발견이 없고 현재 조건에 해당 |
| 지속 중 | 이전 발견이 현재도 같은 조건에 해당 |
| 회복 | 같은 기준의 완전한 현재 데이터에서 조건을 벗어남 |
| 판단 보류 | 이전 발견은 있지만 현재 데이터 또는 해당 그룹의 관찰이 부족 |

상태는 모델 해석이 아닌 서버의 집계로 결정합니다. 회복된 발견이 다시 발생하면 새로 발견으로 기록합니다. 이전 관찰과 조사 요약을 다음 조사에 전달하지만 현재 사실로 단정하지 않도록 합니다. AI가 제시하는 원인 설명은 가설이며 근거가 인과를 입증하지는 않습니다.

기존 테이블을 초기화하지 않고 설정·보고서 JSON에 선택 필드를 추가합니다. 기존 보고서와 과거 재현 시연도 계속 열 수 있습니다. 이력은 업무별 최근 50건이며 전체 활동 기록에서 검색·페이지 조회할 수 있습니다.

## 검증

- `npm test`: 기존 회귀 및 자동 조사·발견 추적 테스트. SQLite 임시 DB를 사용합니다.
- `npm run test:pg`: 실제 PostgreSQL 통합 검증. 공유 테이블 초기화 충돌을 피하도록 파일을 순차 실행합니다.
- `npm run build`: 타입 검사와 프로덕션 빌드.
- `tests/investigation_browser_smoke.py`: 신규 업무, 자동 시연 조사, 지속 추적, 근거·후속 대화, 모바일.
- `tests/history_browser_smoke.py`: 전체 활동 기록의 시연·검색·페이지·탐색.

모델 대역 테스트와 시연은 실제 모델의 추론 품질을 검증하지 않습니다. 실제 OpenAI 호출 검증 여부는 작업 결과에 별도로 기록합니다.

## 발표용 2주 합성 시나리오

`node scripts/seed-task-presentation.mjs <업무 UUID>`로 지정한 기존 업무에 발표용 시나리오를 연결할 수 있습니다. 첫 주는 정상, 둘째 주는 판교점만 16% 감소, 지금 확인하기는 더현대 서울만 18% 감소합니다. 원래 저장 분석은 보존하고 별도 시연 분석을 연결합니다. 실제 DW 매출을 수정하거나 실제 AI를 호출하지 않으며 업무·근거·이력에 합성 시연임을 표시합니다. 기준 주차는 준비 시점에 고정됩니다. 시연 업무의 자동 실행은 꺼진 상태로 준비됩니다.

## 업무 검토부터 보고서까지

업무를 선택하고 결과가 있으면 다음 다섯 단계로 진행합니다.

1. **상황 보고:** 이번 수치와 이전 같은 기준의 실행, 기억하고 있는 업무 맥락을 확인합니다.
2. **업무 상황 확인:** 행사 종료나 운영 변화 등 현장에서 알고 있는 내용을 저장합니다.
3. **함께 조사하기:** AI 또는 규칙 기반 모드를 선택하고 추천 질문이나 직접 입력으로 조사합니다. AI는 집계와 사용자 답변을 보고 다음 도구·확인 질문·행동을 선택합니다. 대화 중에도 추가 지시를 보낼 수 있고 같은 업무에서 다시 열 수 있습니다.
4. **다음 행동:** 예상된 변화/중요/업무상 해결 판단과 추가 조사·다음 회복 확인·담당자 확인 계획을 저장합니다. 사람의 판단은 실제 지표 회복과 별도로 보관합니다. 다음 같은 그룹의 조사에 이 맥락을 전달합니다.
5. **보고서 PDF:** 미리보기를 확인하고 한글 PDF를 내려받습니다. 기간·수치·사용자 상황·해석·판단·후속 계획·이전 비교·조회 근거·주요 대화를 포함합니다.

업무 상황을 바꾸면 새 상황을 반영한 추가 조사를 완료한 뒤 PDF를 만들 수 있습니다. PDF는 확인한 검토·대화 버전을 기준으로 생성하며 다른 수정이 발생하면 다시 확인하도록 안내합니다. 후속 계획 저장은 일정이나 임계값을 자동으로 변경하지 않으며 담당자에게 메시지를 전송하지 않습니다.

검토 상태는 `task_reviews`에 업무/실행/대상별로 보관합니다. PDF 생성은 `pdf-lib`와 함께 배포한 OFL 라이선스 나눔고딕을 사용합니다. 글꼴 라이선스는 `assets/fonts/OFL.txt`에 있습니다.
