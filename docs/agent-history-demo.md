# 지표 감시 시연과 실행 이력

## 시연 준비
1. 최신 main을 내려받고 npm run dev를 실행합니다.
2. 왼쪽 **내 분석 앱 → 감시 실행 이력** 탭으로 이동합니다.
3. **시연 이력 준비 / 불러오기**를 누릅니다. OpenAI 키나 API 호출 없이 준비할 수 있습니다.
4. 최근 8주를 DB에서 다시 집계한 결과와 데이터 보유 시작점의 판단 보류 사례 1건, 총 9건을 저장합니다.
5. 상태에서 **조건 발견**을 고르고 보고서를 펼칩니다. 현재·비교 매출, 증감률, 조건 발견 점포, 상품군·채널 추가 조회를 보여줍니다.
6. **정상**, **판단 보류**를 선택해 다른 사례도 확인합니다.
7. **감시 설정 열기**에서 “매주 월요일 오전 9시 / 직전 완료 주 / 전주 대비 10% 이상 감소” 설정을 확인합니다.

시연 앱과 감시는 자동 실행 **비활성** 상태입니다. 실제 자동 실행을 원하면 설정을 확인하고 활성화해 저장하세요.

명령으로 미리 준비하려면 서버를 실행하기 전에:

    npm run db:demo

## 데이터의 의미
시연 이력은 임의 매출 수치를 넣거나 실제 과거 실행이 있었던 것처럼 날짜를 바꾼 기록이 아닙니다. 현재 샘플 DB의 과거 기간을 실제 집계하고 기존 감시 판정 함수를 그대로 실행한 **과거 재현(replay)** 입니다. 각 기록에 재현 기준 시각, 기록 저장 시각, 실제 분석·비교 기간, 당시 앱 설정과 조건을 보관합니다.

매출 하락 여부는 현재 샘플 데이터에 따라 달라집니다. 실제 DB 집계에서 10% 이상 감소한 주차만 조건 발견으로 표시합니다. 원인 추정이나 인위적인 감소 수치 생성은 하지 않습니다.

- 정기 실행: 서버가 정해진 시간에 실행한 기록.
- 시험 실행: 저장된 감시 설정을 사용자가 즉시 실행한 기록.
- 시연 · 과거 재현: 시연 준비 기능으로 과거 기간을 다시 분석한 기록.

재현 기준 시각은 월요일 한국 시간 오전 9시입니다. 미래 시각을 재현하지 않도록 최신 재현 주차를 제한합니다. 데이터 부족 사례는 보유 시작일 근처에 두 비교 주간이 완전히 포함되지 않는 경우로 판단을 보류합니다.

시연 준비는 기존 거래·예산·고객·설정 데이터를 수정하지 않습니다. 전용 앱·감시와 보고서만 트랜잭션으로 저장합니다. 버튼을 다시 눌러도 기존 시연 감시의 일정·활성화·수정 설정·이력을 덮어쓰지 않고 기존 묶음을 불러옵니다. 시연 묶음을 새로 만들고 싶으면 연결된 시연 분석 앱을 삭제한 후 다시 준비하세요.

## 조회
실행 이력 탭은 모든 에이전트의 기록을 모아 보여줍니다.

- 에이전트, 상태, 실행 유형, 기록일 시작/종료 필터.
- 한국 시간 기준 기록일 필터 (재현 기준일과 구분).
- 필터가 적용된 전체 건수와 상태별 건수.
- 페이지당 5건, 이전/다음 페이지.
- 15초마다 새로고침, 직접 다시 조회.
- 보고서에서 앱과 감시 설정으로 이동.
- 개별 감시 설정 아래의 기존 실행 이력에서도 같은 보고서와 재현 표시 사용.

서버는 페이지 크기 1~50을 지원합니다. 사용자 인증/소유권과 이력 보관 정책은 기존 프로젝트 범위와 같습니다.

## API
- GET /api/metric-agents/history?agent=&status=&kind=&from=&to=&page=1&pageSize=5
- GET /api/metric-agents/history/:runId
- POST /api/metric-agents/demo

새 DB 테이블이나 파괴적 마이그레이션은 필요 없습니다. 기존 metric_agent_runs에 kind=replay와 report.replay 메타데이터를 보관합니다. 사용자 PC의 DB는 Git으로 전달되지 않으므로, 업데이트 후 버튼 또는 npm run db:demo를 한 번 실행하면 해당 PC에 이력이 저장됩니다.

## 검증
기존 SQLite 격리 테스트 및 실제 PostgreSQL 통합 테스트에 다음 검사를 추가했습니다.

- 실제 DB 재집계와 재현 보고서 숫자/판정 일치.
- 월요일 09:00, 감소율 10%, 비활성 생성.
- 재실행 중복 방지와 일정/원본 거래 보존.
- 전체 이력 조회, 상태/유형/에이전트 필터, 한국 날짜 경계.
- 페이지 이동 중 중복 없음, 상세 보고서.
- 잘못된 필터, 없는 이력, API/다른 사이트 변경 차단.

GitHub Actions는 실제 Chromium에서 시연 준비, 필터, 페이지 이동, 보고서, 재조회, 앱/감시 이동, 모바일 가로 넘침을 검사합니다. 화면과 서버 로그는 history-browser-results 아티팩트에 남깁니다.
