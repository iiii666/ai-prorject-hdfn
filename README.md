# 현대백화점 DW · DB 기반 분석 워크스페이스

React + TypeScript 화면, Node.js 조회 API, **SQLite 데이터베이스**로 구성한 로컬 분석 서비스입니다. 최초 실행 시 고객·상품·주문·결제·캠페인·앱 세션·예산 데이터를 생성해 DB에 저장합니다. 화면의 숫자는 SQL 조회 결과이며, 이전 버전의 배율 계산·고정 KPI는 제거했습니다.

실제 현대백화점 데이터가 아닌 생성 샘플입니다. 로그인 인증, 외부 DW, 생성형 AI는 연결하지 않았습니다. 인사이트는 SQL 집계를 설명하는 규칙 기반 요약입니다.

## 기존 프로젝트 업데이트

개발 서버가 실행 중이면 `Ctrl+C`로 종료한 뒤 VS Code 터미널에서 실행하세요.

```bash
cd ~/ai-prorject-hdfn
git pull --ff-only
npm ci
npm run dev
```

브라우저: **http://localhost:5173** (사용 중이면 터미널에 표시된 다음 포트)

**Node.js 24 LTS 이상**이 필요합니다. `node -v`로 확인하세요. Node 내장 `node:sqlite`를 사용하므로 별도 DB 프로그램, Docker, Python 설치가 필요 없습니다. Node 버전에 따라 SQLite ExperimentalWarning이 표시될 수 있지만 정상 실행됩니다.

처음 설치한다면:

```bash
git clone https://github.com/iiii666/ai-prorject-hdfn.git
cd ai-prorject-hdfn
npm ci
npm run dev
```

VS Code에서 `파일 → 폴더 열기`로 프로젝트를 여세요. `code` 명령이 등록돼 있다면 `code .`도 가능합니다.

## 데이터 생성 및 보존

- DB 파일: **`data/hyundai-dw.sqlite`**
- 최초 실행일(KST)을 기준으로 최근 **210일**의 샘플 거래를 생성합니다.
- 점포 3개, 고객 3,600명, 상품 48개, 캠페인 6개와 약 4만 건의 주문을 생성합니다.
- 상품별 수량·단가로 주문 결제액을 계산합니다. 취소 주문은 매출에서 제외됩니다.
- 캠페인 대상과 주문을 연결해 전환율·기여 매출을 계산합니다.
- 완료된 모바일 주문은 구매 세션과 연결됩니다.
- 캠페인 집행액과 `CRM 캠페인` 부문 예산 집행액이 일치합니다.
- 같은 DB가 있으면 재생성하지 않습니다. 서버 재시작 후에도 데이터와 관리자 설정이 유지됩니다.
- 최근 7/30/90일은 **DB 생성 당시의 데이터 기준일**을 기준으로 합니다. 날짜를 직접 지정할 수도 있습니다.
- DB 파일과 WAL/SHM 파일은 Git에 올리지 않습니다. 중단한 서버의 `data/` 폴더를 별도로 보관해 백업할 수 있습니다.
- `DW_DB_PATH`로 다른 DB 파일을 지정할 수 있습니다. `DW_SEED_END=YYYY-MM-DD`는 새 DB의 샘플 기준일을 지정하는 개발·테스트 옵션입니다.

## 지표 정의

- 매출: 완료 주문의 결제액 합계. 표시 단위는 원 또는 만/억 원입니다.
- 활성 구매 고객: 선택 기간·점포·채널에서 완료 주문이 있는 고유 고객.
- 누적 구매 고객: 같은 점포·채널에서 조회 종료일까지 구매 이력이 있는 고유 고객.
- 신규 첫 구매: 같은 점포·채널의 최초 구매일이 조회 기간 내에 있는 고객.
- 재구매율: 조회 기간 내 완료 주문이 2건 이상인 고객 / 기간 내 구매 고객.
- 휴면 위험: 같은 점포·채널의 마지막 구매가 조회 종료일 기준 30일 이상 이전인 고객.
- 고객 등급 구성: 누적 구매 고객의 회원 등급. 세그먼트끼리는 중복될 수 있습니다.
- 캠페인 전환율: 기간 내 대상 지정 고객 중 같은 기간 해당 캠페인에 귀속된 완료 주문이 있는 고객 / 대상 고객. 캠페인 간 중복 포함, 전체는 대상 수로 가중 집계합니다.
- 앱 활성 사용자: 선택 기간 앱 세션의 고유 고객. 일평균 활성은 일별 고유 고객 합계 / 조회 일수입니다.
- 앱 퍼널: 세션 단위 방문 → 상품 조회 → 장바구니 → 완료 주문. 오프라인 채널에는 앱 세션이 없습니다.
- 전기 대비: 조회 시작일 직전의 **동일한 일수**와 비교합니다. 샘플 보유 기간 이전의 데이터는 없습니다.
- 데이터가 없으면 수량/금액은 0, 비율의 분모가 0이면 `—`, 전기 기준이 0이면 `비교 기준 없음`으로 표시합니다.
- 예산과 캠페인 집행률은 선택 기간 내 일별 배정·집행 합계 기준입니다.

리니지의 연결선은 **SQL 뷰가 직접 참조하는 테이블·뷰 관계**입니다. 외래 키 관계나 API 코드가 직접 조회하는 모든 관계를 뜻하지 않습니다. 외부 Kafka/Snowflake/Airflow 등은 사용하지 않습니다. 적재 이력은 최초 샘플 생성 실행의 기록이며 예약 배치가 아닙니다.

## 명령어

```bash
npm run dev       # API(3001) + Vite(5173) 함께 실행
npm run db:seed   # DB 생성/확인 (기존 데이터 보존)
npm test          # 격리된 메모리 DB에서 SQL/API 정합성 테스트
npm run build     # TypeScript 검사 + 프론트엔드 빌드
npm start         # API + 빌드된 화면을 http://localhost:3001 에서 실행
```

`npm run preview`도 빌드된 화면과 API를 함께 실행합니다. 개발 서버와 동시에 실행하면 API 포트 3001이 충돌하므로 기존 프로세스를 먼저 종료하세요. 서버는 로컬 컴퓨터(`127.0.0.1`)에만 바인딩합니다.

## 구조

```text
server/
  schema.sql       # 테이블, FK/제약, 인덱스, 집계 뷰
  db.mjs           # SQLite 연결, 결정적 샘플 데이터 생성
  analytics.mjs    # SQL 집계, 지표 정의, 카탈로그·주문 조회
  index.mjs        # HTTP API, CSV, 설정 저장, 정적 화면 제공
  seed.mjs         # DB 초기화 CLI
src/
  App.tsx          # 공통 화면, 조회 조건, 로딩·오류 처리
  AnalysisPages.tsx # 통합/고객/매출/캠페인/앱/예산 화면
  DataManagement.tsx # 카탈로그/리니지/관리자 설정
  api.ts           # API 타입, 요청 및 취소 처리
  components.tsx   # 공통 카드, 차트, 테이블
  data.ts          # 메뉴 이름, 날짜·그래프 유틸리티 (샘플 KPI 없음)
tests/
  database.test.mjs # 거래 정합성, 필터, 집계 대사, API 검증
```

## 주요 API

| 메서드 | 경로                                                                       | 내용                                              |
| ------ | -------------------------------------------------------------------------- | ------------------------------------------------- |
| GET    | `/api/bootstrap`                                                           | 점포·채널 옵션, DB 기간, 설정                     |
| GET    | `/api/analytics?start=YYYY-MM-DD&end=YYYY-MM-DD&store=1&channel=모바일 앱` | 모든 분석 화면 집계                               |
| GET    | `/api/orders?...&page=1&q=123`                                             | 같은 필터의 주문 검색/페이지 조회                 |
| GET    | `/api/catalog`                                                             | 실제 DB 자산/컬럼/행 수, SQL 의존 관계, 적재 이력 |
| GET    | `/api/export?...`                                                          | 조회 조건별 통합 지표 CSV                         |
| PATCH  | `/api/settings`                                                            | `{workspaceName, alertsEnabled}` 저장             |
| GET    | `/api/health`                                                              | API와 샘플 DB 상태                                |

`store`와 `channel`을 생략하면 전체입니다. 날짜를 생략하면 데이터 기준일로부터 최근 30일이며 `days=7` 등으로 조정할 수 있습니다. 최대 조회 기간은 365일입니다.

## 검증

`npm test`는 별도의 메모리 DB를 사용하여 로컬 데이터 파일을 변경하지 않습니다. 주문상품 합계와 결제액, 필터별 매출, 차트·상품군·점포 합계, 캠페인/CRM 예산, 앱 퍼널, 주문 검색/페이지, 빈 결과, 잘못된 요청, 설정 저장, 신규 거래 반영을 검증합니다. GitHub Actions에서 테스트와 빌드를 실행합니다.
